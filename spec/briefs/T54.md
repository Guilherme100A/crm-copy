## O que as dependências entregaram (código no checkout)

### T22 — equipe e convites: `apps/api/src/routes/team/index.ts` (serviços `packages/core/src/team/service.ts`, `packages/core/src/invitations/service.ts`)
- `GET /api/team` (`team.view`) → `{ items: MemberDto[] }`, já ordenado owner < admin < member e depois por nome. `MemberDto` = `{ id, company_id, user_id, role, permission_keys: string[] | null, effective_permissions, user: { id, name, email }, created_at }`. **Não traz departamentos** (ver Atenção 4).
- `PATCH /api/team/:userId` (`team.edit`) `{ role? , permission_keys? }` (aceita também `{ member: {...} }`) → `{ member }`. `permission_keys: null` ou `[]` volta à matriz do papel. Regras (`TeamService.update`): `role: 'owner'` → 422 `use_transfer_ownership`; owner não é alterado por terceiros (403); owner não troca o próprio papel (409 `owner_must_transfer`); permissões explícitas só owner/admin.
- `DELETE /api/team/:userId` (`team.delete`) → `{ removed: true }`.
- `POST /api/team/:userId/transfer-ownership` (só o owner; alvo precisa ser admin, senão `target_not_admin`) → `{ owner: MemberDto, previous_owner: MemberDto }`. O owner atual vira admin.
- `GET /api/permissions/definitions?role=` → `{ groups: [{ key, keys }], always_granted, owner_only, role?, defaults? }` (`permissionDefinitions`).
- Convites (gestão): `GET /api/team/invitations?kind=member|platform&status=pending|accepted|declined|expired&search&page&limit` → `{ items: InvitationDto[], page, status_counts: { total, pending, accepted, declined, expired } }`. Permissão: `team.view` (member) ou `settings.platform_invitations.view` (platform).
  - `POST /api/team/invitations { kind, email, role: admin|member }` → 201 `{ invitation, invitation_link }`.
  - `POST …/:id/resend` → `{ invitation, invitation_link }`. Limite: 429 `RATE_LIMIT` com `details.error_code = 'resend_limit'` ("Limite de 3 reenvios por dia atingido", `DEFAULT_MAX_RESENDS_PER_DAY = 3`) ou `resend_cooldown` (60 s).
  - `POST …/:id/cancel` → `{ invitation }`. `POST …/:id/link` → `{ invitation_link }` (gera token novo; o link anterior deixa de valer).
  - `InvitationDto` = `{ id, kind, email, role, status, created_at, updated_at, expires_at, can_resend, resends_remaining_today, invited_by: { id, name } | null, company }`.
- Escopo de chat do membro (T31, `apps/api/src/routes/departments/index.ts`): `GET /api/departments/members/:memberId/scope` (`team.view`) e `PUT` (`team.edit`) `{ department_ids?, connection_ids? }` → `{ scope: { member_id, department_ids, connection_ids } }`. **`memberId` = `MemberDto.id`** (company_members.id), não o `user_id`. Listas: `GET /api/departments/all` → `{ items }`; `GET /api/connections?limit=100` (exige `connections.view`).

### Permissões em `@crm/shared` (`packages/shared/src/permissions/`)
- `catalog.ts`: `PERMISSION_CATALOG` (grupos na ordem do modal: dashboard, sales, chat, kanban, flows, contacts, mass_dispatch, webhooks, connections, facebook, ai_usage, team, settings), `SETTINGS_AREAS` (13 áreas, inclui `message_templates`), `ALWAYS_GRANTED_PERMISSIONS` (`profile.view`, `settings.global_variables.*`), `OWNER_ONLY_PERMISSIONS` (`settings.platform_invitations.*`).
- `resolve.ts`: `normalizePermissions(keys)` (marcar edit/delete ⇒ view + `settings.view`; `chat.block` ⇒ `chat.view`) e `revokePermission(keys, key)` (tirar view tira edit/delete; tirar `chat.view` tira `chat.block`; always_granted não sai). Use as duas no modal (AC-T54-02); não reimplemente.
- `defaults.ts`: `DEFAULT_ROLE_PERMISSIONS`, `COMPANY_ROLES`.

### T32 — acesso de suporte: `apps/api/src/routes/support-access/index.ts` (serviço `packages/core/src/support-access/service.ts`)
- **Lado empresa** (owner/admin; os outros → 403 `owner_admin_only`): `GET /api/support-access/requests?status=pending|approved|rejected|cancelled|all` (padrão `pending`) → `{ requests }`; `POST …/requests/:id/approve` → `{ request, grant }` (12 h); `POST …/requests/:id/reject` → `{ request }`; `GET /api/support-access/grants` → `{ grants }`; `DELETE /api/support-access/grants/:supportUserId` → `{ grant }`.
- **Lado suporte** (só `system_role = support`): `GET /api/support/access-requests` → `{ requests }`; `POST /api/support/access-requests/lookup { email }` → `{ accounts }`; `POST /api/support/access-requests { email, company_id? | account_id? }` → 201 `{ request }` (422 `account_not_found` | `account_required`; 409 `request_pending` | `grant_active`); `POST …/:id/resend`; `DELETE …/:id` (cancela); `GET /api/support/access-grants` → `{ grants }`; `GET /api/support/access-grants/:companyId/flows`.
- DTOs: `SupportAccessRequestDto { id, status, support_user_id, support_name, support_email, company_id, company_name, decided_at, resent_at, created_at, updated_at }`; `SupportAccessGrantDto { id, support_user_id, name, email, company_id, company_name, request_id, expires_at, created_at }`.
- **SSE** (`packages/shared/src/realtime/events.ts`, `permission` null): `support_access.requested { request }`, `.granted { request, grant }`, `.rejected { request }`, `.revoked { grant }`, `.cancelled { request }`. Publicados no stream da empresa e no do suporte. O `request` do evento traz o DTO completo (o schema é `looseObject`).
- **403 `support_access_expired`** (decisão do Orquestrador na T32, `apps/api/src/middleware/company.ts`): suporte com `X-Company-Id` de empresa cuja concessão expirou ou foi revogada. Vale para TODA `/api/*`, inclusive `GET /api/auth/profile`.
- Perfil do suporte (`AuthService.listCompanies`): empresas com concessão ativa aparecem com `role: 'member'`, `effective_permissions` = escopo da concessão e `support_access: { grant_id, expires_at }`.

## Atenção (achados do levantamento)
1. **Tela do suporte fora dos Paths:** `apps/web/src/routes/support/access.tsx` (pedir acesso por e-mail com lookup, listar pedidos com reenviar/cancelar, listar concessões e fluxos). Peça a liberação ao Orquestrador. A UI fica em `features/settings-support/`, e a rota só importa.
2. **Modal global (AC-T54-05) fora dos Paths:** precisa montar em `apps/web/src/app/shell/app-shell.tsx`, com import ESTÁTICO do módulo que chama `onRealtime('support_access.requested', …)`. Registro em módulo lazy (aba de configurações) não entra no SSE já aberto (`docs/licoes.md`). O modal: owner/admin; texto "{nome} ({e-mail}) solicitou acesso temporário de 12h…", "Recusar" / "Aprovar por 12h", contagem quando houver mais de um, e avança para o próximo pendente. Carga inicial por `GET /api/support-access/requests` (status padrão `pending`), e `.cancelled`/`.granted`/`.rejected` removem da fila.
3. **`support_access_expired` bloqueia o suporte inteiro:** com o `X-Company-Id` antigo, até `GET /api/auth/profile` dá 403. `loadSession` só trata 401, então o shell trava e o suporte não chega a `/support/access`. Para corrigir, ao receber 403 com `details.error_code === 'support_access_expired'`: `setActiveCompany(null)`, invalidar `profileQueryKey`/`resetQueries` e `router.invalidate`. Isso é em `apps/web/src/lib/http.ts` ou `lib/session.ts`, ambos FORA dos Paths. Peça liberação aditiva.
4. **Filtro por departamento (AC-T54-01) sem dado:** `MemberDto` não tem `departments` (a ref §3.4 tem). Alternativas: (a) N chamadas a `GET /api/departments/members/:id/scope` + `GET /api/departments/all` no cliente; (b) acrescentar `departments[]` em `TeamService.list` (`packages/core/src/team/service.ts`, FORA dos Paths). Pergunte antes.
5. **Aba `support_access` = owner/admin:** não existe chave de permissão. `SettingsTab` não tem `ownerAdminOnly`, e o hub não filtra por papel. Acrescentar o campo em `tabs.ts` é aditivo, mas o filtro em `apps/web/src/routes/settings/index.tsx` está FORA dos Paths (foi liberado só para a T53). Sem isso, um member vê a aba e leva 403 `owner_admin_only`.
6. **Paths `routes/settings-*`** não estão no `ROUTE_DIR`, então virariam URLs `/settings-team` etc., que não existem no produto. As telas são abas do hub: use `features/` + `i18n/`. A página `/settings/invitations` (ref §2; `access.ts` já tem a permissão) seria `routes/settings/invitations.tsx`, também fora, e não tem AC.
7. **AC-T54-04:** os cards e o filtro são da aba `platform_invitations` (`kind=platform`, `status_counts`). Por padrão, só o owner tem `settings.platform_invitations.*` (`OWNER_ONLY_PERMISSIONS`). "Copiar link" = `POST …/:id/link`, que invalida o link anterior. Mostre "Limite de 3 reenvios por dia" pelo 429 `resend_limit` e por `can_resend`/`resends_remaining_today ≤ 0`.
8. **E2E do AC-T54-05:** o seed E2E não tem usuário `support` (`SEED_USERS` = platformAdmin, owner, admin, member), e só existem as rotas `/__e2e/reset` e `/__e2e/mail`. Criar o suporte exige um seed ou uma rota em `scripts/e2e`, FORA dos Paths. Combine com o Tester e o Orquestrador.
9. **Suporte sem empresa ativa não abre SSE:** `useRealtime` só conecta com `session.company`. Na tela do suporte, atualize por refetch (foco ou intervalo), e não por SSE.
