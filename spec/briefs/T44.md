## O que as dependências entregaram (código na main)

### T28 — `apps/api/src/routes/flows/index.ts` (store `packages/core/src/flows/store/store.ts`)
- **Permissões:** `flows.view` lê, `flows.edit` faz as mutações, `flows.delete` exclui fluxo e pasta.
  - Matriz (`packages/shared/src/permissions/defaults.ts`): member tem `flows.view` e `flows.run`; owner e admin têm também `edit` e `delete`.
- **`GET /api/flows?folder_id=<uuid|root>&status=draft|active|paused|archived&search`** → `{ items: FlowDto[], folders: FolderDto[] }`.
  - Não tem paginação. A paginação "de–até de total" da tabela fica no cliente.
  - Ordem: `folder_id, position, created_at`. Busca `ilike` só no nome.
  - Sem `folder_id`, devolve todos os fluxos e todas as pastas. Com `folder_id`, `folders` são só as filhas diretas.
- **`FlowDto`** (`toFlowDto`): `{ id, name, description, status, folder_id, position, published_version, nodes_count, created_at, updated_at }`. O `FlowDto` local de `features/flow-editor/canvas/api.ts` não tem `folder_id`/`position`: defina o seu em `features/flows/api.ts`.
- **`FolderDto`:** `{ id, name, color, parent_id, position, created_at, updated_at }`. Não traz contadores: conte fluxos e subpastas no cliente. Cores: `FLOW_FOLDER_COLORS` = `blue|green|purple|orange|red|yellow|gray`.
- **Criar e editar fluxo:**
  - `POST /api/flows { name?, description?, folder_id? }` → 201 `{ flow }`, sempre com status `draft` (a ref diz `active`; vale a API).
  - `PATCH /api/flows/:id { name?, description? }`.
  - `POST /api/flows/:id/duplicate` → 201, nome "`<nome> (cópia)`", mesma pasta, `position + 1`.
- **Status:** `POST /api/flows/:id/{activate|pause|archive|unarchive}` (`flows.edit`). Fluxo inválido no activate → 422 `details.errors`; o helper `activationIssues` está em `features/flow-editor/canvas/api.ts`.
- **Mover e reordenar fluxo:**
  - `POST /api/flows/:id/move { folder_id: uuid|null }`.
  - `POST /api/flows/:id/reorder { position: int≥0 }` grava SÓ a posição desse fluxo, sem renumerar os vizinhos. Calcule as posições no cliente.
- **Pastas:**
  - `GET /api/flow-folders?parent_id=<uuid|root>` → `{ items }`.
  - `POST /api/flow-folders { name, color?, parent_id?, position? }` → 201 `{ folder }`.
  - `PATCH /api/flow-folders/:id` aceita `name, color, parent_id, position`.
  - `POST /api/flow-folders/:id/move { parent_id: uuid|null }`.
  - `DELETE /api/flow-folders/:id` (`flows.delete`). Os fluxos e as subpastas da pasta excluída vão para a raiz.
  - Mover para si mesma ou para uma descendente → 409 `CONFLICT` ("a pasta não pode ser movida para uma subpasta dela mesma"), checado em `assertNotDescendant`. Bloqueie também no cliente (ref §3.2).
- **Impacto da exclusão (`impact.ts`):** `GET /api/flows/:id/deletion-impact` (`flows.view`) → `{ active_runs, total_runs, connection_flow_configs[{kind,id,name?}], business_hour_configs[…], referenced_by_flows[{id,name,node_ids}] }`.
- **`DELETE /api/flows/:id`** → `{ deleted: true }`. Se houver config de conexão ou de horário apontando para o fluxo, responde 409 `CONFLICT` com `details.error_code = 'flow_referenced'` e `details.references`.

### T43 — `apps/api/src/routes/flow-share/index.ts`
- `GET /api/flows/:id/share-code` (`flows.view`) → `{ code }`. São 10 caracteres de `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, e um código ativo é reaproveitado.
- `POST /api/flows/import { codes: string[1..50] }` (`flows.edit`) → 201 `{ items[{ code, flow, warnings }], errors[{ code, reason: 'invalid_code' }] }`.
  - A cópia sai em `draft`, na raiz.
  - Os códigos são deduplicados e comparados sem diferenciar maiúsculas.
  - Separe o textarea por vírgula ou quebra de linha (ref §2.3).
- Não fazem parte da lista: `GET /api/flows/:id/export` e `POST /api/flows/import-json` (opcionais) e `flow-runs` (`/api/flows/:id/runs`, `flows.run`).

## Atenção (achados do levantamento)
1. **Divergência na URL da pasta.** A ref usa `?folder_id=N`; o AC exige `?folder=`. Siga o AC. O valor é o uuid da pasta, e ausente = "Sem pasta" (raiz) ou todas, conforme você decidir. Registre a escolha em Notas e combine com o Tester.
2. **AC-T44-03 "configs" × backend.** A ref §2.3 diz que as configs são removidas ou desativadas. A API **bloqueia** a exclusão com 409 `flow_referenced` quando há `connection_flow_configs` ou `business_hour_configs`.
   - O modal deve mostrar o impacto e, se houver referências bloqueantes, desabilitar "Excluir" ou exibir o 409 com a lista.
   - Não contorne isso no cliente. Mudar a regra exigiria `apps/api/src/routes/flows/{index,impact}.ts` (Paths da T28), fora dos Paths. Pergunte ao Orquestrador se ele quiser o comportamento da ref.
3. **Provável 500 no import com o limite atingido.** Em `flow-share/index.ts`, o `POST /api/flows/import` chama `store.createFlow` sem `store404`. O `LIMIT_REACHED` da T95 provavelmente vira 500 em vez de 409. Isso fica fora dos Paths: reporte em Notas e trate o erro de forma genérica.
4. **O reorder não renumera.** Para "Solte aqui para reordenar" persistir, envie `reorder` com posições que respeitem a ordem (por exemplo, renumere os afetados com N chamadas). Para reordenar pastas, use `PATCH /api/flow-folders/:id { position }`.
5. **Faltam contadores e paginação na API.** Use `GET /api/flows` sem filtro para montar a árvore e as contagens. A tabela pagina no cliente.
6. **Itens do menu sem API:** "Traduzir" (§5.7) não tem rota. Deixe-o fora, sem placeholder. "Remover da pasta" = `move { folder_id: null }`.
7. **Filtro de status:** a ref oferece "Todos / Ativos / Pausados / Pastas", e a API aceita também `draft` e `archived`. Defina o search param (ex.: `?status=`) e registre-o como contrato (licoes: search params são contrato).
8. **Marca neutra:** `F-NO-BRAND` reprova "leona" (a ref cita "Leona AI"/"Leona Pay").
