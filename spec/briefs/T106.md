## O que as dependências entregaram (código na main)
### T101 — Gerenciador: `GET /api/meta/structure-bundle` (`apps/api/src/routes/meta-structure/index.ts`, perm `facebook.campaigns`)
- Query: `level` (`campaign|adset|ad`), `status_filter` (`active|all`; aceita também `status`), `date_preset` (`today|yesterday|7d|30d|month|custom`), `since`/`until` (ou `start_date`/`end_date`), `display_currency`, `ad_account_ids` (ids LOCAIS; `a,b` ou `ad_account_ids[]`), `force_refresh=1`, `async=1` (202 enquanto não `ready`) — `packages/core/src/meta-ads/structure/params.ts`.
- `BundleEnvelope` (`structure/service.ts`): `{ bundle_key, status: loading|partial|refreshing|ready, campaign[], adset[], ad[], targets_done, targets_total, errors[{ad_account_id, fb_ad_account_id, error}], display_currency, since, until, status_filter, warnings[], cached, generated_at }`. `warnings` pode ter `rate_limited` (veio do último bundle pronto, `cached: true`), `fx_rate_missing:<FROM>-><TO>` e `no_ad_accounts`.
- `BundleRow` (`structure/account.ts`): `id, name, status, objective?, campaign_id/name?, adset_id/name?, ad_account_id, fb_ad_account_id, ad_account_label, currency, daily_budget, lifetime_budget, *_display, metrics`. Métricas (`structure/metrics.ts`): `meta_spend, purchase_value_meta, purchases_pixel, conversations_meta, meta_link_clicks, meta_impressions, cost_per_purchase_meta, cost_per_lead_meta, purchase_value_leona, purchases_leona` (as internas ficam null até a T105).
- SSE `meta.bundle.progress` (perm `facebook.campaigns`): `{ bundle_key, status, targets_done, targets_total, errors?, warnings? }`; o cliente relê o GET.
### T103 — edição: `PATCH|PUT /api/meta/structure-entities/:id` (`routes/meta-entities/index.ts`, `facebook.campaigns`)
- Corpo `{ level, fb_ad_account_id, status?, name?, daily_budget?, lifetime_budget? }` → `{ success: true, entity }`. Erros: 422 `VALIDATION_ERROR`, 404, 429 `RATE_LIMIT` (`details.error_code: 'meta_rate_limited'`, `retry_at`), 502 `UPSTREAM_ERROR` (`meta_update_failed`). A regra nível × campo é do serviço (`meta-ads/mutations/service.ts`).
### T104 — Pixel: `routes/meta-pixels/index.ts` (tudo `facebook.pixel`)
- `GET /api/meta/pixels` → `{ items: PixelConfigDto[] }` com `masked_pixel_id`, `masked_access_token`; `GET /:id?include_access_token=true` traz `pixel_id`/`access_token` para a edição; `POST` (201 `{ pixel }`), `PUT /:id` (`access_token` vazio/null = manter), `DELETE /:id` (204). Campos: `name ≤ 255`, `pixel_id`, `access_token`, `platform`, `auto_send_sales` (aceita envelope `pixel_config`).
### T99 — Perfis e OAuth (`routes/meta-profiles/index.ts`, `routes/meta-oauth/index.ts`)
- `GET /api/meta/profiles` → `{ items: MetaProfileDto[] }` (`id, fb_user_id, fb_user_name, picture_url, active, token_expires_at, ad_accounts[], ad_accounts_count, ad_accounts_included_count, …`); conta: `MetaAdAccountDto { id, fb_account_id, account_id, name, currency, account_status, included_in_dashboard }`.
- Gestão (`facebook.profiles` + owner/admin ou platform_admin, `requireMetaManager`): `DELETE /api/meta/profiles/:id` (204), `POST /:id/refresh-ad-accounts` → `{ profile }`, `PUT /api/meta/ad-accounts/:id { included_in_dashboard }` → `{ ad_account }`, `POST /api/meta/oauth/start { profile_id? }` → `{ oauth_url }`. Member com `facebook.profiles` mas sem ser admin leva 403 nessas: desabilite.
- Callback: `GET /api/meta/oauth/callback` SEMPRE redireciona para `/facebook/profiles?meta_oauth=success|error[&meta_message=…]`.

## Atenção (achados do levantamento)
1. **Rede no harness.** `scripts/e2e/api.ts` (fora dos Paths) não injeta `metaFetch`/`metaConfig` e não chama `configureMetaAds` (`apps/worker/src/jobs/meta-ads/index.ts`). Consequências: OAuth, "Atualizar lista" e o bundle com contas reais chamariam `META_GRAPH_URL` (padrão `https://graph.facebook.com/v26.0`, `.env.example`); com `async=1` o job `meta-sync` falha ("dependências não configuradas") e o bundle fica `loading`. Duas saídas: (a) liberação aditiva de `scripts/e2e/api.ts` para subir o `FakeMetaGraph` (`packages/core/src/meta-ads/client/testing/fake-graph.ts`: `start()`, `addUser`, `setAdAccounts`, `issueCode`, `setStructure`, `setInsights`, `failAccount`, `setUsage`, `failNext`) e passar `metaConfig`/`configureMetaAds`; (b) E2E só com `page.route` nas rotas `/api/meta/*` (estados de AC-02 e erros de AC-04). Decida com o Orquestrador antes do Tester; a T90 também mexe nesse arquivo.
2. **Sem perfil no seed:** `GET /api/meta/profiles` → `[]` e o bundle volta `warnings: ['no_ad_accounts']` sem chamar a Meta (estado "sem perfil/contas" testável direto). O toast do OAuth é testável abrindo `/facebook/profiles?meta_oauth=success` (ou `error&meta_message=…`) e conferindo que os params somem.
3. **Rate limit (AC-02):** use `warnings.includes('rate_limited')` + `cached`. Erros por conta: `errors[]` (1 conta → toast "<conta>: <erro>"; várias → "N conta(s) com aviso…", ref §5.2 nº 7).
4. **Ordem das colunas (AC-03):** `localStorage` com chave versionada por empresa (ref §3.4/§5.2 nº 12), ignorando chaves obsoletas; arrastar no desktop, setas com `pointer: coarse`. Envolva todo acesso em try/catch (`lib/storage.ts` tem `readStorage`/`writeStorage`).
5. **Rótulo pareado:** "`${APP_NAME} / Meta`" (e "/ Pixel"). As chaves `purchases_leona`/`purchase_value_leona` passam no `F-NO-BRAND` (o `\b` não separa no `_`), mas nenhum texto visível pode dizer "Leona".
6. **Moeda de exibição:** não há coluna na empresa (pendência T101). Mande `display_currency` na query e guarde a escolha no cliente; registre nas Notas.
7. **Filtro de status:** o servidor usa `status_filter=active|all`. Se puser na URL, NÃO use `?status=` (tipo unido do TanStack; é do `/chats`): ex. `?fb_status=`. Ao trocar de nível, volta para `active` e nome vazio (ref §5.2 nº 11).
8. **AC-04:** só uma edição por vez; nome desabilitado em `level=ad`; orçamento só com `fb_ad_account_id`; vírgula decimal aceita; campo vazio não é enviado.
9. Mantenha um contêiner `data-testid="page-facebook"` (id do placeholder).
10. **AC-01 por sub-rota:** a guarda global deixa entrar em `/facebook/*` com qualquer uma das 3 permissões. Cada sub-rota sem a sua permissão também redireciona para a primeira permitida (ordem campaigns → pixel → profiles, ref §2). Para o teste "só `facebook.pixel`", ajuste as permissões de um member pela API de equipe: `PATCH /api/team/:userId { permission_keys: ['facebook.pixel', …] }` (`team.edit`, `apps/api/src/routes/team/index.ts`).
11. **Cache do cliente** (ref §5.2): 5 min por chave (empresa + contas + datas + nível + escopo), só para bundles `ready` sem `rate_limited`; limpar ao trocar de empresa, ao editar e ao alternar conta. "Atualizar" manda `force_refresh=1` e inicia o cooldown de 30 s (use relógio injetável / `page.clock` no teste, nunca espera real).
12. **Sobreposição:** a T105 (TODO) preenche `purchases_leona`/`purchase_value_leona` no core; a UI só formata null como `—`. A T102 (E2E final) vai passar por estas telas: testids estáveis.
