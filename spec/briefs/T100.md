## Critérios de aceitação (SPEC.md, "### T100")

## O que as dependências entregaram (código na main)
Todo `/api/admin/*` e `/api/platform/*` exige `platform_admin` (`requirePlatformRole`). Os demais usuários recebem 403 (AC-T95-01).
### T95 — `apps/api/src/routes/admin/index.ts` (serviço `packages/core/src/admin/service.ts`)
- `GET /api/admin/users?page&limit&search&skip_total` → `{ items: AdminUserDto[], page }`.
  - `page` = `PageMeta { page, limit, total_count, total_pages, has_more }` (`packages/shared/src/pagination.ts`).
  - `DEFAULT_PAGE_LIMIT = 20` e o máximo é 100. A busca procura em nome e e-mail.
- `AdminUserDto`: `id, name, email, system_role (user|platform_admin|support), role (client|client_employee|admin|support), role_label, personal_whatsapp, locale, last_company_id, companies_count, created_at, updated_at`.
- `POST /api/admin/users` aceita `{ user: {...} }` ou o corpo plano: `name, email, password, password_confirmation?, personal_whatsapp?, system_role?, role?` → 201 `{ user }`.
  - Mensagens do servidor: "E-mail inválido" (regex `^\S+@\S+\.\S+$`), "A senha deve ter no mínimo 6 caracteres" e "A confirmação não confere com a senha".
- `PUT /api/admin/users/:id`: o e-mail é aceito e IGNORADO (imutável). Senha vazia ou null = não muda. Resposta: `{ user, password_changed }`.
- `GET /api/admin/users/:id/companies` → `{ items: [{ account_id, account_name, role, role_label, active }] }`.
- `GET /api/admin/companies?page&limit&search&active` → `{ items: AdminCompanyDto[], page }`.
  - O DTO traz `owner`, `owner_email`, `users_count`, `limits` (`connections|ai_agents|members|flows|webhooks`, null = ilimitado), `inbox_limits` e `mass_dispatch_quota`.
  - `GET /:id` acrescenta `usage`.
  - `PATCH /api/admin/companies/:id { active?, limits?, inbox_limits? }` responde 422 se vier vazio.
- Também existem `GET|PATCH /api/admin/mass-dispatch-settings`, `GET|PATCH /api/admin/companies/:id/mass-dispatch-quota { bonus_delta }`, `GET /api/admin/statistics?start_date&end_date` e `GET /api/admin/audit-logs`.
  - `statistics`: `new_companies`, `new_users`, `totals{companies, active_companies, users, connections, connected_connections}`, `messages`, `messages_per_day[]`. Sem dinheiro: a Visão geral NÃO tem faturamento.
### T96 — `apps/api/src/routes/admin-ops/index.ts` (`packages/core/src/admin-ops/*`)
- **Avisos:** `GET|POST /api/admin/announcements`, `GET|PATCH|PUT|DELETE /api/admin/announcements/:id` (o DELETE responde 204).
  - Query `search, page, limit (padrão 20), active, skip_total` → `{ items, page }`.
  - Campos: `title` (1–200), `message` (1–5000), `image_url?`, `url?`, `announcement_type info|warning|error|success` (padrão info), `priority`, `expires_at` (ISO com offset), `active`.
- **Banners:** as mesmas rotas em `/api/admin/banners`. `image_url` é obrigatório na criação; `title` é opcional (nome interno).
- `image_url` e `url` precisam ser **http(s)** (`httpUrl` em `announcements.ts`). `""` limpa um campo opcional.
- **Cliente:** `GET /api/announcements` e `GET /api/banners` → `{ items }`, só ativos e não expirados, por prioridade. Qualquer membro com empresa ativa pode chamar. Os dois também vêm em `GET /api/dashboard/bootstrap`.
- **Saúde:** `GET /api/admin/health` → `{ status ok|degraded, checked_at, queue_prefix, queues[], redis, … }`. Use `checked_at` para o "atualizado às".
- **Sessões:** `GET /api/admin/wa/sessions?company_id&state&orphan` → `{ profile, items: AdminWaSessionDto[], total }`.
  - **No modo extensão (`WA_RPC_PROFILE=ai-manager`) a rota responde 404.** Sem gateway, responde UPSTREAM_ERROR.
- **Segredos:** `GET /api/admin/platform-secrets`, `GET|PUT|DELETE /:key` (`PUT { value }`). Só escrita: a leitura traz `configured, source db|env|null, hint`.
- **Uso de IA:** `GET /api/admin/ai/usage?from&to&company_id&provider&model` → `{ from, to, items[{company_id, company_name, provider, model, count, …, credits}], totals }`.
### Carteira (T37) — `apps/api/src/routes/platform-ai/index.ts`
- `POST /api/platform/companies/:id/ai/topups { credits>0, note }` e `POST /api/platform/companies/:id/ai/adjustments { credits≠0, note }` → 201 `{ entry, wallet }`.
  - A `note` é obrigatória ("Informe a nota", 1–500).
- `GET /api/platform/ai/wallets?negative&limit` lista as carteiras.

## Atenção (achados do levantamento)
1. **Pop-up no app do cliente (AC-03) precisa de arquivo fora dos Paths.**
   - Nada na web consome `announcements` hoje.
   - Para o pop-up aparecer em qualquer tela, ele precisa ser montado em `apps/web/src/app/shell/app-shell.tsx` (T23, fora dos Paths). A T54 (`SupportApprovalModal`) e a T59 (`WalletChip`) fizeram isso com liberação aditiva.
   - Peça a liberação de 1 import e 1 elemento (ex.: `features/admin/announcement-popup.tsx`). Até lá, reporte BLOCKED parcial.
   - "Fechar" só oculta localmente (14 §14). Guarde os ids fechados por usuário com `readStorage`/`writeStorage`, dentro de try/catch.
2. **Upload de imagem (AC-03): falta backend.**
   - `image_url` exige uma URL http(s).
   - `POST /api/media` (`routes/media/index.ts`) exige empresa ativa e `chat.view`. Ele devolve um id servido por `GET /api/media/:id`, que também é escopado por empresa. O cliente de outra empresa não veria a imagem.
   - Peça ao Orquestrador uma rota de upload global do admin, por exemplo em `apps/api/src/routes/admin-ops/**` (Paths da T96), que devolva uma URL pública. Não invente uma URL no cliente.
   - Até lá: campo de URL com prévia (`<img>`) e o salvar desabilitado sem imagem no banner (20 §3.7).
3. **Modo extensão (AC-04):** a web não sabe o perfil do gateway: nada em `apps/web` nem em `@crm/shared` expõe isso. Para esconder a aba Sessões, use o 404 de `GET /api/admin/wa/sessions` (sonda ao abrir `/admin`), ou peça um campo novo. Registre a escolha nas Notas.
4. **"Atualizado às HH:MM":**
   - Saúde: use `checked_at`.
   - Sessões e IA não trazem horário: use o `dataUpdatedAt` da query.
   - O botão Atualizar faz `refetch`.
5. **Marca neutra:** o id da aba na ref é `leona_ai` e o rótulo é "Leona AI". `F-NO-BRAND` reprova "leona": use `ai` / "IA".
   - Abas sem backend (servidores, webhooks, tradutor, comprovante) ficam FORA. As do AC são overview, users, accounts, announcements, banners, saúde, sessões e IA. A cota de disparos é opcional (T95 tem rota).
6. **Search params:** `tab` já existe com tipos diferentes (`/settings` string; `/profile`, `/agentes`, `/welcome` enum). Use `z.string().optional().catch(undefined)` e valide no componente, com replace para `overview`.
   - Busca e página ficam em estado local (o AC pede que reiniciem ao trocar de aba). Não reuse `?status=` nem `?start_date=` com outro tipo (licoes).
7. **Harness:** o seed tem `platform@demo.test` (platform_admin), `owner@`, `admin@` e `member@demo.test` (`packages/db/src/seed/base.ts`).
   - A API do harness usa `FakeWaGateway`, então `/api/admin/wa/sessions` funciona.
   - O modo extensão não é testável no harness sem `WA_RPC_PROFILE`. Prove esse ramo com `page.route` devolvendo 404.
8. Sobreposição: nenhuma outra tarefa em andamento toca `features/admin/**`. O `app-shell.tsx` também é visado por T107/T108 (TODO). Faça só acréscimo.

## Lições de docs/licoes.md (as mais relevantes)
- Search params do TanStack são um tipo unido entre rotas: não reuse um nome com outro tipo. (T44, T88)
- E2E: capture a URL depois que ela estabilizar (`await expect(page).toHaveURL(...)`), principalmente após o replace de aba. (T53)
- Testids são contrato: `admin-<coisa>`, `admin-item-<campo>-${id}`. Combine-os no relatório.
- i18n nas 3 línguas (`admin.json`). Não rode prettier em arquivos compartilhados.
- Harness em segundo plano: `E2E_IGNORE_STDIN=1 node scripts/e2e/serve.mjs`. O seed não tem avisos, banners nem conexões: crie-os pela API no teste.
- Nunca chame API real de terceiros.
