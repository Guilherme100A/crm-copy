## Critérios de aceitação (SPEC.md, "### T58")
- **AC-T58-01** Respostas rápidas: tabela com busca e paginação; editor de ações reordenáveis com mídia; atalho duplicado mostra o erro do servidor.
- **AC-T58-02** Modelos de mensagem: editor com prévia em formato de chat e variáveis do contato de exemplo; não existe nenhuma menção a aprovação da Meta.
- **AC-T58-03** Variáveis globais: prefixo `g_` mostrado fixo; tipo número rejeita texto no cliente.
- **AC-T58-04** Campos personalizados: abas "Customizados" e "Sistema" (sistema só leitura de valor, descrição editável); etiquetas com cor e contagem de contatos.
- **AC-T58-05** Membro sem permissão de edição vê as listas sem botões de criar/editar/excluir; layout `mobile` em cartões.

## O que as dependências entregaram (código na main)

### T35 — conteúdo: `apps/api/src/routes/content/index.ts` (serviço `packages/core/src/content/service.ts`, regras em `rules.ts`)
- **Respostas rápidas:** `GET /api/quick-replies?page&limit&search&type` → `{ items, page }`; `POST` `{ shortcut, actions: [{ type, order?, config }] }` → 201 `{ quick_reply }`; `GET|PATCH|PUT /api/quick-replies/:id`; `DELETE` → `{ deleted: true }`.
  - Tipos de ação (`QUICK_REPLY_ACTION_TYPES`, `packages/db/src/schema/crm/content.ts`): `send_message {message_text}`, `send_multi_media {media_type: image|video|audio|document, media_id, caption?}`, `send_sticker {sticker_id}`, `send_contact {contact_name, contact_phone}`.
  - Regras: pelo menos 1 e no máximo 20 ações; atalho normalizado `[a-z0-9_ -]` (`normalizeShortcut`, `SHORTCUT_MAX` = 60).
  - Atalho duplicado → 409 `CONFLICT` com `details.error_code = 'shortcut_taken'` e `details.fields[{ path: 'shortcut' }]`.
  - `QuickReplyDto` tem `id, shortcut, actions[{ id, type, order, config }], preview, created_at, updated_at`.
- **Modelos internos:** `GET /api/message-templates?page&limit&search` → `{ items, page }`; `POST` `{ name, header?: { type: none|text|image|video|document, text?, media_id? }, body, footer?, buttons?: [{ type: reply|url|phone, text, url?, phone? }] }` → 201 `{ template }`; `GET|PATCH|PUT|DELETE /api/message-templates/:id`. Máximo de 10 botões. Permissões `settings.message_templates.*`, uma área nova da T35 em `SETTINGS_AREAS`.
- **Prévia:** `POST /api/content/render { template? | template_id? | quick_reply_id?, contact_id? }` (sem permissão extra) → texto renderizado. Botões viram menu numerado ou links, como em `renderTemplateContent` (`rules.ts`).
- **Variáveis globais:** `GET /api/global-variables?page&limit&search`, `POST { name, description?, type: text|number, value }` → 201 `{ global_variable }`, `GET|PATCH|PUT|DELETE /api/global-variables/:id`.
  - Nome imutável; o servidor aplica o prefixo `g_` (`globalVariableName`: `[A-Za-z0-9_]`, até 64).
  - Número validado com `NUMBER_VALUE_RE = /^-?\d+(\.\d+)?$/` (replique no cliente).
  - `settings.global_variables.*` é SEMPRE concedida (`ALWAYS_GRANTED_PERMISSIONS`), então todo membro edita variáveis.
- **Mídia e figurinhas para as ações:** `POST /api/media` (multipart, campo `file`) → 201 `{ media }`; `GET /api/stickers` → `{ items }`. As duas rotas exigem `chat.view`, que member e admin têm por padrão. Helper pronto: `composerApi.upload(file, name)` e `stickersQuery()` em `apps/web/src/features/chat-composer/api.ts`.
- Os DTOs não estão em `@crm/shared`. Defina tipos locais (a T85 fez o mesmo em `chat-composer/api.ts`: `QuickReplyDto`, `StickerDto`). A web não importa `@crm/core`.

### T26 — etiquetas e campos
- **Etiquetas** (`apps/api/src/routes/labels/index.ts`): `GET /api/labels` → `{ items: LabelDto[] }`, sem paginação. `LabelDto` = `{ id, name, color, contacts_count, created_at }` (`packages/core/src/labels/service.ts`).
  - `POST { name, color }` (`.strict()`, cor `#RRGGBB`, `LABEL_COLOR_RE`) → 201 `{ label }`; `PATCH|PUT /api/labels/:id`; `DELETE` → 204.
  - Permissões `settings.labels.view|edit|delete`.
- **Campos** (`apps/api/src/routes/custom-fields/index.ts`): `GET /api/custom-fields` → `{ items: CustomFieldDto[] }` com `{ key, description, example_value, system }`. Os 8 de sistema vêm primeiro, com `system: true` (`SYSTEM_CUSTOM_FIELDS` em `packages/core/src/custom-fields/service.ts`).
  - `POST { key, description? }` → 201 `{ custom_field }`. Chave de 2–255 caracteres, minúscula, sem `.`/`{}`; duplicada → 409.
  - `PATCH /api/custom-fields/:key { description }` (encode a chave). Não há DELETE.
  - Permissões `settings.fields.view|edit`.

## Atenção (achados do levantamento)
1. **AC-T58-04 × backend:** a ref 17 §3.D diz que a descrição de campo BOT é editável pelo mesmo PATCH. Mas `CustomFieldsService.updateDescription` (`packages/core/src/custom-fields/service.ts`) rejeita chave de sistema com 422 "Campos de sistema não são editáveis". Isso fica fora dos Paths (só web). Pergunte ao Orquestrador antes de implementar; não contorne no cliente.
2. **Membro padrão tem `settings.quick_replies.edit`** (exceção da matriz em `packages/shared/src/permissions/defaults.ts`) e sempre tem `global_variables.*`. Para o AC-T58-05, "sem permissão de edição" vale para modelos, campos e etiquetas no papel member, ou para lista explícita de permissões.
3. **AC-T58-02:** não escreva "Meta", "WABA", "aprovação" nem "whatsapp_business_account" (a regra `F-NO-CLOUD-API` reprova este último em `.ts`). Marca neutra: `F-NO-BRAND` reprova "leona".
