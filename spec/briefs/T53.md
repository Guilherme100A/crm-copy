## Critérios de aceitação (SPEC.md, "### T53")
- **AC-T53-01** `/settings?tab=accounts` mostra dados da empresa; salvar fica desabilitado com nome vazio; fuso só editável por owner/admin.
- **AC-T53-02** Desativar empresa abre diálogo crítico listando os efeitos e exige confirmação; reativar volta ao normal.
- **AC-T53-03** Departamentos: criar com paleta de 10 cores ou cor própria, buscar e excluir com diálogo de confirmação.
- **AC-T53-04** Horários: escolher a conexão (com status), adicionar intervalo (padrão 09:00–18:00), validação igual à do servidor; salvar persiste.
- **AC-T53-05** Aba inválida ou sem permissão na URL é trocada (replace) pela primeira aba permitida; no `mobile` as abas viram um select pesquisável.

## O que as dependências entregaram (código na main)

### API de empresas (T22) — `apps/api/src/routes/companies/index.ts`
- `GET /api/companies/:id` → `{ company }`; `PUT /api/companies/:id` body `{ name?, slug?, description?, time_zone?, connection_status_emails_enabled?, active? }` (aceita também `{ account: {...} }` ou `{ company: {...} }`) → `{ company }`.
- `DELETE /api/companies/:id` = desativar → `{ company, paused_session_ids }`. Reativar = `PUT { active: true }`.
- DTO no fio: `CompanyDto` em `packages/core/src/companies/service.ts` (`id, name, slug, description, active, time_zone, connection_status_emails_enabled, deactivated_at, created_at, updated_at`) + `role`. Atenção: `companySchema` de `packages/shared/src/dto/company.ts` tem `settings` e NÃO bate com o fio; defina o tipo local na feature.
- Regras do serviço (`CompanyService.update`): editar exige `settings.accounts.edit`; `time_zone` só owner/admin (member → 403); `active` só owner.
- Fusos: `COMPANY_TIME_ZONES` (12 IANA) fica em `packages/core/src/companies/service.ts`. A web só depende de `@crm/shared` (não importe `@crm/core`), então replique a lista na feature. `DEFAULT_TIME_ZONE` está em `@crm/shared`.
- Empresa desativada: `companyActiveGuard` (`apps/api/src/routes/companies/guard.ts`) responde 403 com `details.error_code = 'company_inactive'` em todas as rotas fora de auth/companies. Hoje nenhum código da web trata esse código (grep vazio). Depois de desativar, as outras abas falham.
- Realtime: `company.updated` existe em `packages/shared/src/realtime/events.ts` e o serviço publica ao salvar.

### T31 — departamentos: `apps/api/src/routes/departments/index.ts`
- `GET /api/departments?page&limit&search` (paginado, `PageResponse`: `{ items, page: { page, limit, total_count, total_pages, has_more } }`, ver `packages/shared/src/pagination.ts`), `GET /api/departments/all` → `{ items }`.
- `POST /api/departments` `{ name, color? }` (ou `{ department: {...} }`) → 201 `{ department }`; `PATCH|PUT /api/departments/:id` → `{ department }`; `DELETE /api/departments/:id` → 204.
- Permissões: `settings.departments.view|edit|delete`. Erros 422 `VALIDATION_ERROR` com `details.fields[{ path, message }]` (cor fora de hex, nome > `DEPARTMENT_NAME_MAX` = 60 em `packages/core/src/departments/service.ts`). Cor padrão `#3B82F6` (`DEFAULT_DEPARTMENT_COLOR`, `packages/db`).
- DTO `DepartmentDto` em `packages/core/src/departments/service.ts`.

### T31 — horários: `apps/api/src/routes/business-hours/index.ts`
- `GET /api/business-hours/:connectionId` → `{ config }`; `PUT /api/business-hours/:connectionId` body `{ active, action_type?: 'message'|'flow', message_text?, flow_id?, business_hours?: [{ day_of_week, start_time, end_time, active? }] }` → `{ config }`. Substitui config e TODOS os intervalos numa transação.
- Sem config, o GET devolve config vazia (`id: null`, `active: false`, `business_hours: []`). Máx. 70 intervalos (`MAX_INTERVALS`).
- Validação do servidor a replicar no cliente (AC-T53-04): `intervalErrors()` e `parseTime()` em `packages/core/src/business-hours/is-open.ts` (arquivo puro, sem imports). Regras: dia 0–6; `HH:MM`; início ≠ 24:00; fim > início; ativo + `message` exige texto; ativo + `flow` exige `flow_id`. Erros vêm com paths `business_hours.<i>.<campo>`, `message_text`, `flow_id`.
- Permissões: `settings.business_hours.view|edit`.
- Conexões para o select: `GET /api/connections?limit=100` (`apps/api/src/routes/connections/index.ts`, exige `connections.view`) → `{ items: ConnectionView[] }` com `status` em `pending|connecting|connected|paused|disconnected|banned` (`packages/core/src/connections/status.ts`). Fluxos para o select: `GET /api/flows` (exige `flows.view`).

### T36 / T23 — web
- Hub `/settings`: `apps/web/src/routes/settings/index.tsx` (T23) já filtra `SETTINGS_TABS` por `hasAny` e `hiddenForSupport`, faz o replace para a primeira aba visível e aceita `?tab=` e `?company_tab=` no `validateSearch`. Testids: `page-settings`, `settings-tab-<id>`.

- HTTP: `api.get/post/put/patch/delete` e `HttpError { status, code, details }` em `apps/web/src/lib/http.ts`; `fieldMessage(err, path)` em `apps/web/src/features/auth/api.ts` extrai a mensagem de campo de um 422.

## Atenção (achados do levantamento)
1. **AC-T53-05 (select pesquisável no mobile)** depende de `apps/web/src/routes/settings/index.tsx`, que pertence à T23 e está FORA dos Paths da T53. Hoje o hub tem só `<nav>` com rolagem horizontal. O replace já existe. Não edite esse arquivo sem autorização: reporte BLOCKED/pergunta ao Orquestrador (liberar o arquivo como aditivo ou mover o critério).
2. Membro padrão tem `settings.business_hours.view`, mas não `connections.view` (`packages/shared/src/permissions/defaults.ts`). O select de conexões leva 403: trate com estado vazio.
3. `GET /api/flows` exige `flows.view`, que member e admin têm.
