## Critérios de aceitação (SPEC.md, "### T115")
**Entregáveis:** servidor de autorização OAuth 2.1 para o endpoint MCP da empresa. Inclui:
- metadados (`/.well-known/oauth-authorization-server` e `oauth-protected-resource`);
- registro dinâmico de cliente;
- `/authorize` com login do usuário e tela de consentimento (escolhe a empresa);
- PKCE S256 obrigatório;
- `/token` com access token curto + refresh token (hash no banco);
- revogação;
- credencial `auth_type: oauth` com status `pending → connected` (com `connected_client_hint`) → revogada;
- UI de criação que mostra a URL e os passos do conector.

ACs:
- **AC-T115-01** Fluxo completo com cliente de teste: registro dinâmico → `/authorize` (login + consentimento) → código → `/token` com PKCE válido → token aceito no endpoint MCP; PKCE inválido ou ausente → `invalid_grant`.
- **AC-T115-02** A credencial passa de `pending` para `connected` com o nome do cliente; revogar invalida access e refresh tokens na hora (401 no endpoint MCP).
- **AC-T115-03** O token OAuth só dá acesso à empresa escolhida no consentimento, com as mesmas ferramentas somente leitura do T94.
- **AC-T115-04** Refresh token usado duas vezes (reuso) revoga a cadeia inteira.
- **AC-T115-05** Na UI, criar credencial do tipo OAuth mostra a URL do servidor MCP e as instruções do conector; o status muda para "Conectada · <cliente>" ao recarregar após a conexão (desktop e `mobile`).

## O que a dependência entregou (T94, código na main)
- **Schema** `packages/db/src/schema/crm/mcp.ts`: tabela `mcp_credentials`.
  - Colunas: `id`, `companyId`, `name`, `authType` (`MCP_AUTH_TYPES = ['static','oauth']`), `tokenHash` (SHA-256, nulo para oauth), `tokenHint`, `expiresAt`, `lastUsedAt`, `revokedAt`, `createdByUserId`.
  - **Não há colunas de status nem `connected_client_hint`.**
- **Serviço** `packages/core/src/mcp/credentials.ts` (`McpCredentialsService`):
  - `MCP_TOKEN_PREFIX = 'crm_mcp_'` e `MCP_ENDPOINT_PATH = '/api/mcp'`;
  - `endpointUrl()` lê `API_PUBLIC_URL`;
  - `createSchema` tem um `.refine(v => v.auth_type === 'static', 'Credencial OAuth ainda não disponível')`;
  - `authenticate(token)` aceita só tokens `crm_mcp_` com `authType === 'static'`;
  - `McpCredentialStatus = 'active'|'expired'`;
  - hash por `hashToken` (`packages/core/src/platform/tokens.ts`, SHA-256 hex).
- **Servidor MCP** `packages/core/src/mcp/server.ts`:
  - `MCP_TOOL_NAMES = ['list_contacts','get_contact','list_connections','list_flows','list_chats']`, todas somente leitura;
  - `handleMcpRequest(req, { db, companyId })` é Streamable HTTP sem sessão.
- **Rotas** `apps/api/src/routes/mcp/index.ts`:
  - `GET /api/mcp_credentials` → `{ mcp_credentials, mcp_endpoint_url }`;
  - `POST` → 201 `{ mcp_credential, token, mcp_endpoint_url }`;
  - `DELETE /api/mcp_credentials/:id`;
  - permissões `settings.mcp.view|edit|delete`;
  - `app.all('/api/mcp')`: sem auth → 401 com `WWW-Authenticate: Bearer realm="mcp"`; empresa inativa → 403 `company_inactive`.
- **Públicas** (`apps/api/src/middleware/public-routes.ts`): `{ method: '*', path: '/api/mcp' }`, e `isInboundHook()` deixa `/api/mcp` fora do CSRF. A sessão (`sessionAuth`), o CSRF e o `companyContext` valem só para `/api/*` (`apps/api/src/app.ts:38-41`). Rotas fora de `/api` (ex.: `/.well-known/*`) não passam por eles.
- **Web** `apps/web/src/features/settings-mcp/`:
  - `mcp-tab.tsx`, aba `mcp_credentials` em `features/settings/tabs.ts`;
  - testids `mcp-credentials`, `mcp-create`, `mcp-endpoint-url`, `mcp-credential-row`, `mcp-status`, `mcp-create-dialog`, `mcp-name`, `mcp-expiration`, `mcp-create-submit`, `mcp-token`, `mcp-revoke`, `mcp-revoke-confirm`;
  - `api.ts`: `McpCreateInput.auth_type: 'static'` e `createBody(name, days)`.
- **Login com retorno:** `/login?redirect=` com `safeRedirect` (`@/lib/redirect`). Rotas desconhecidas exigem só sessão (`app/guard.ts` `decide` → `canAccess`).

   - `packages/core/src/mcp/credentials.ts`: remover o `refine` que recusa `oauth`; `authenticate` aceitar o access token OAuth; status `pending|connected` + `connected_client_hint` no DTO;
   - `apps/api/src/routes/mcp/index.ts`: 401 com `WWW-Authenticate: Bearer resource_metadata="<API>/.well-known/oauth-protected-resource…"` (descoberta do conector);
   - `apps/web/src/features/settings-mcp/{mcp-tab.tsx,api.ts}`: escolha do tipo, URL + passos e "Conectada · <cliente>" (AC-05).
   Alternativa sem tocar o `mcp.ts` da T94: guardar status e cliente nas tabelas próprias de `mcp-oauth.ts`, com FK para `mcp_credentials.id`.
2. **Tela de consentimento:** precisa de uma rota web nova (ex.: `apps/web/src/routes/oauth/consent.tsx`), fora dos Paths (só `features/mcp-oauth` está). `routeTree.gen.ts` é compartilhado. Peça a pasta de rota. Sem sessão, o guard já leva a `/login?redirect=`: confira que `safeRedirect` preserva a query do pedido.
3. **Rotas públicas novas:** `/.well-known/*` fica fora de `/api`. Se `register`, `authorize`, `token` e `revoke` ficarem sob `/api/mcp-oauth/*`, acrescente-os em `PUBLIC_API_ROUTES` e no `isInboundHook` (CSRF), de forma aditiva.
   - A aprovação do consentimento é a única rota que exige sessão: `POST` com cookie + `X-Requested-With`.
4. **Empresa escolhida (AC-03):** o consentimento lista as empresas do usuário (`CompanySummary` do perfil) e exige vínculo, além de `settings.mcp.edit`, por exemplo.
   - O grant fica preso à empresa e à credencial `pending`.
   - Defina e documente como o cliente "liga" na credencial: por exemplo, a URL do conector carrega o id da credencial, ou o consentimento escolhe a credencial pendente.
5. **PKCE e tokens:**
   - só `S256` (`plain` → `invalid_request`);
   - código de uso único e curto;
   - access curto + refresh com rotação, guardando o **hash** dos dois;
   - reuso de refresh → revoga a família inteira (AC-04);
   - `redirect_uri` exatamente igual ao registrado;
   - erros no formato `OAuthErrorResponseSchema` (`invalid_grant`, `invalid_client`…).
6. **Testes:** o "cliente de teste" é local, usando `app.request()`, os helpers `client/auth` do SDK e `pkce-challenge` (já no lockfile, 5.0.1). Nunca use o Claude real nem rede.
7. **Migration:** tabelas novas (clientes, códigos, tokens). A última na main é `0033_t96_admin_ops.sql`. Siga a lição abaixo.

## Decisões do Orquestrador (2026-10-17)
