## O que as dependências entregaram (código na main)

### T40 — `apps/api/src/routes/connections/index.ts` (serviço `packages/core/src/connections/service.ts`)
Leitura exige `connections.view`, escrita e ações `connections.edit`, exclusão `connections.delete`. Owner e admin têm as três (`packages/shared/src/permissions/defaults.ts`); member NÃO tem nenhuma, nem a `view`. Todas as rotas aceitam o envelope `{ connection: {...} }`.
- `GET /api/connections?search&status&page&limit(≤100, padrão 20)` → `{ items: ConnectionView[], page: { page, limit, total_count, total_pages, has_more }, status_counts }`.
  - `status` ∈ `CONNECTION_UI_STATUSES` = `pending|connecting|connected|paused|disconnected|banned` (`packages/core/src/connections/status.ts`).
  - `status_counts` conta TODAS as conexões da busca, antes do filtro de status: use nos cards de contagem.
  - A busca cobre nome e telefone (`ilike`). A ordem é `created_at` crescente.
- `ConnectionView` = `{ id, name, session_id, phone_number, status, session_state, badges[], connection_state, last_disconnect_reason, disconnected_at, connected_at, notify_sent_by_me, ephemeral_duration, save_contacts_enabled, scheduled_for_deletion_at, requires_restart, proxy: { protocol, host, port, username, has_password } | null, created_at, updated_at }`.
  - `badges` ⊂ `warming|degraded|requires_restart|scheduled_deletion`: são o "aquecimento/saúde" do AC-T71-01.
- `POST /api/connections { name (2–100), phone? }` → 201 `{ connection }`. Com o limite atingido → `LIMIT_REACHED` com `details: { limit, used }`.
- `GET /api/connections/:id`, `PUT|PATCH /:id { name?, notify_sent_by_me? }` → `{ connection }`.
- `POST /:id/connect|disconnect|restart` → `{ connection }`. O `connect` faz `resume` se a sessão estiver PAUSED; nos outros casos, `startQr`.
- `POST /:id/schedule-deletion` (`connections.delete`).
- `GET /:id/qr` (exige `edit`) → `{ qr_code (data URL) | null, generated_at }`.
- `POST /:id/pairing-code { phone }` → `{ code }`. O telefone é DDI+número só com dígitos, `^[1-9]\d{6,14}$` (`PAIRING_PHONE_RE`; o `+` inicial é tolerado).
- `POST /:id/proxy { protocol: http|https|socks5, host, port 1–65535, username?, password? }` e `DELETE /:id/proxy`.
  - Os dois marcam `requires_restart: true`, que é o "aviso de reinício". A senha nunca volta: só vem `has_password`.
- `POST /:id/instance-settings { ephemeral_duration: off|1d|7d|90d, save_contacts_enabled, notify_sent_by_me }`. Não há `apply_to_all`.
- `GET|PATCH /:id/whatsapp-profile`: perfil opcional, não está nos ACs.
- Códigos de erro: `NOT_FOUND`, `VALIDATION_ERROR` (`details.fields[{path,message}]`), `LIMIT_REACHED`, `INVALID_TRANSITION`, `UPSTREAM_ERROR`.

### T43 — "Parar todos os fluxos": `apps/api/src/routes/flow-runs/index.ts:189`

### T47 — eventos realtime (`packages/shared/src/realtime/events.ts:250-293`; projetor em `packages/core/src/connections-status/projector.ts`)

- `connection.status_changed` `{ status, session_state, connection_state, badges }`.
- `connection.qr_updated` `{ qr_code }` (edit) e `connection.pairing_code` `{ code }` (edit).
- `connection.connected` `{ name, phone_number, connected_at }`.
- `connection.disconnected|disconnected_alert|banned_alert` `{ name, phone_number, reason, status_code, status, disconnected_at }`.

## Atenção (achados do levantamento)
1. **Harness: QR e conectado (AC-T71-02).**
   - `POST /__e2e/wa/emit` (`apps/api/src/e2e/index.ts:158`) só repassa o evento aos ouvintes do fake e ao stream. Ele NÃO muda o estado interno da sessão no `FakeWaGateway`.
   - Os eventos que o próprio fake emite (`startQr` → `session.qr`) não chegam ao stream: no harness, o `connect` não gera `connection.qr_updated`. Para o QR, use `GET /:id/qr` (devolve `FAKE_QR_DATA_URL`). O "atualiza" o Tester prova emitindo `{ type:'session.qr', session_id, qr:'data:image/png;base64,…' }`.
   - Ao emitir `session.connection` com `state: 'open'`, o worker do harness (sem gateway configurado) publica `status_changed` com `status:'connected'` e `connection.connected`.
   - Porém o `GET /api/connections` continua derivando o estado da sessão `NEW` do fake e devolve `connecting`. Um `invalidateQueries` depois do evento DESFAZ o "conectado" na tela.
   - **Peça ao Orquestrador** a liberação aditiva de `apps/api/src/e2e/index.ts` para uma rota tipo `POST /__e2e/wa/sessions/:id/state { to }`, que chame `FakeWaGateway.setSessionState` e publique os eventos no stream.
   - Sem essa rota, aplique o payload de `status_changed` direto no cache com `setQueryData` e não refaça a busca logo em seguida. Registre a escolha nas Notas.
2. **Limite (AC-T71-05), lacuna de backend:** nenhuma rota da empresa expõe `limits.connections`; só o admin (platform) lê. Hoje a web só descobriria o limite depois de um `LIMIT_REACHED`.
   - Para deixar o botão desabilitado ANTES do clique, é preciso mexer em `apps/api/src/routes/connections/index.ts` e `packages/core/src/connections/service.ts` (paths da T40), fora dos Paths. Sugestão: incluir `limit: { max, used } | null` no `GET /api/connections`.
   - Peça ao Orquestrador. Não invente o limite no cliente.
3. **Retomar/Cancelar (AC-T71-04), lacuna de backend:** a ref 08 §5.13 cita `resume_paused_flows`/`cancel_paused_flows`, mas não existe rota para isso. O `flow.resumed` está definido e ninguém o publica.
   - Os runs pausados na queda ficam com `wait.paused_by = 'connection'` e `wait.connection_id`. A rota exige backend fora dos Paths (`flow-runs`, T43, ou `connections`, T40).
   - **Peça ao Orquestrador.** Para o E2E, o modal precisa de runs `waiting` num chat da conexão antes da queda (`close` e depois `open` via `/__e2e/wa/emit`). Confirme com o Tester como montar esse cenário.
4. A contagem de execuções ativas no "Parar todos" (ref §5.12) não tem rota. O AC não exige a contagem: não invente.
5. **Marca e escopo:** o AC-T71-04 proíbe "API Oficial", "Embedded Signup" e "imune a ban". Não crie seletor de tipo (`meta_cloud` é [REQUER WABA]), slots, "Adicionar slots" nem proxy por cidade. Use marca neutra.
6. **Member** não tem `connections.view` (o nav esconde o item). Esconda as ações conforme `connections.edit`/`.delete` e o "Parar todos" conforme `flows.run`. QR e código exigem `edit`.
